## 一、技术隐患（未修，低优先级）

### 1. 界面靠错误文案的关键字归位

- 位置：`src/bond_profit/ui/record_dialog.py`（`("名称", "name")`、`("代码", "code")`… 映射表）；来源为 `src/bond_profit/domain/validation.py` 返回的中文错误句子
- 现状：界面按句子里是否含"名称/代码/日期/价格/数量/备注"决定把错误挂到哪个输入框下；匹配不到就归入"通用错误"
- 触发条件：修改校验提示措辞（例如把"价格"写成"单价"）却未同步映射表
- 后果：提示照常出现、内容照常正确，只是**显示位置**落到"通用错误"行；校验结论与数据保存不受影响
- 若要修：让校验返回结构化 `(字段, 消息)`，同步调整 `record_dialog.py` 与相关测试

### 2. 金额转换异常未被服务层捕获

- 位置：`src/bond_profit/application/sales_service.py`（只 `except RepositoryError`）；`src/bond_profit/domain/money.py`（`yuan_to_cents` 抛 `ValueError`）
- 现状：`create_record` / `update_record` 均先 `normalize` + `validate_record` 再转换，校验已保证价格 > 0 且最多两位小数，因此该 `ValueError` 当前不可达
- 触发条件：将来放松或绕过领域校验
- 后果：万一发生，异常会进入全局异常钩子（写完整堆栈日志 + 中文提示弹窗），不会静默失败

### 3. 界面层直接引用数据层类型

- 位置：`src/bond_profit/ui/backup_page.py`（`from bond_profit.infrastructure.backup import BackupInfo`）
- 现状：直接把 `BackupInfo` 当展示模型用，跨越了 "ui → application" 的分层约定
- 触发条件：将来调整备份元数据结构
- 后果：无功能影响，仅耦合偏紧
